Security Architecture

Zero Servers. Zero Databases. 100% Client-Side.

ReadmeCraft runs entirely inside your browser sandbox. We never store, log, or transmit your Personal Access Tokens or profile drafts to any server.

1. In-Memory Execution: When you provide a GitHub Personal Access Token to commit your README, the token is held strictly in JavaScript heap memory during that specific HTTPS request to api.github.com. It is never written to localStorage or disk.

2. Local Storage Persistence: Profile draft content and theme preferences are stored exclusively on your device in your browser's localStorage. You can clear them at any time with a single click.

3. DPDP Act & GDPR Compliant: Built in accordance with India's Digital Personal Data Protection Act, 2023 and GDPR guidelines with transparent notices and grievance redressal at privacy@readmecraft.org.

Common Questions

Frequently Asked Questions

Is ReadmeCraft really 100% free?

Yes. ReadmeCraft is free, open source under the MIT License, and requires no subscription, paid tiers, or account creation.

How does one-click publishing work?

You provide a GitHub Personal Access Token with Contents: Read and write scope. ReadmeCraft creates your special username/username repository if it doesn't exist yet, fetches the latest commit SHA, and commits your new README.md directly via GitHub REST APIs.

Is my Personal Access Token safe?

Completely safe. Your token is never logged, never stored in cookies or localStorage, and is sent exclusively from your browser to https://api.github.com. As soon as the modal closes, it is purged from memory.

Can I download the Markdown and push manually?

Yes. You can copy the raw Markdown to your clipboard or download a formatted README.md file with one click, and commit it using your standard Git CLI workflow.

Can I add custom sections or custom Markdown?

Yes. ReadmeCraft includes a dedicated Custom Markdown module where you can embed any custom markdown tables, sponsor widgets, badges, or personal copy.

How are GitHub API rate limits handled?

Unauthenticated public profile and repository queries are cached in your browser for 10 minutes to protect against GitHub's 60 req/hour unauthenticated rate limit.
